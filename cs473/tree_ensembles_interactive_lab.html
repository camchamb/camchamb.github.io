Hyperparameter guide

ParameterWhat it controlsTypical effect
n_estimatorsNumber of trees / stagesMore trees reduce variance, increase compute; boosting may overfit if stages keep growing.
max_depthMaximum path lengthShallow trees are smoother and higher-bias; deep trees can memorize noise.
min_samples_splitMinimum rows required to create a splitHigher values regularize trees and reduce tiny, unstable branches.
max_featuresCandidate features considered at a splitSmaller values decorrelate random-forest trees; too small can weaken each tree.
max_samplesRows used by each estimatorSubsampling increases diversity; very small samples can raise bias.
learning_rateContribution of each boosting stageSmaller steps often need more stages but can generalize better.
Random forest vs. boosting: the key conceptual difference

Random forests build many trees independently (often in parallel) using bootstrap samples and random feature subsets. Their predictions are averaged or voted, primarily reducing variance. Gradient boosting builds trees sequentially: each new tree tries to correct the current ensemble's errors. It can reduce bias, but is more sensitive to learning rate, number of stages, and overfitting.

Why can an ensemble outperform one tree?

A single deep tree has high variance: small changes in the training data can change its structure. If individual trees make imperfect but not perfectly correlated errors, averaging their predictions can cancel some of that noise. Diversity is therefore important—not just the number of trees.

What is out-of-bag (OOB) intuition?

With bootstrap sampling, each tree typically leaves out roughly 36.8% of training examples. Those out-of-bag examples can act as a validation set for that tree. This simulator uses a separate held-out test set instead, so its displayed metrics are easier to interpret consistently across methods.
