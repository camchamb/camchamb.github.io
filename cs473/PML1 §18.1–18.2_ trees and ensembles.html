18.1.1 Model: a tree is a piecewise-constant function

A regression tree partitions input space into axis-aligned regions Rj and predicts a constant in each: f(x)=Σj wj·1(x∈Rj). Here wj is the mean of the training y in the region. Dashed curve = true function.

Why: each internal node asks one question, “is xd ≤ t?”, so a root-to-leaf path is a conjunction of such tests, which is exactly one rectangle. Depth D gives at most 2D regions. More regions means a closer fit to the training data, up to one leaf per point.

18.1.2 Fitting: greedy split search

Finding the best tree is NP-complete, so CART grows it greedily. At each node, pick the feature d and threshold t that minimise the weighted impurity of the two children: cost = (|DL|/|D|)·H(DL) + (|DR|/|D|)·H(DR). Drag the threshold and watch the cost.

feature impurity H
Why greedy works at all: sorting a feature once lets you score every candidate threshold with running class counts, so one node costs O(d·n log n). Why Gini or entropy, not error rate: try “misclassification”. Its curve is flat over wide ranges, so many splits tie even when one clearly purifies the children. Gini and entropy are strictly concave in p, so they reward any split that makes a child purer, even when the majority class doesn’t change.

18.1.3 Regularization: how big should the tree be?

A fully grown tree reaches zero training error by memorising noise. Limit depth, or require a minimum leaf size (both are forms of early stopping). Cost-complexity pruning, the other option in the text, grows the full tree and then removes the least useful splits.

Why: training error only goes down as the tree grows. Validation error drops, then rises once leaves start fitting individual noisy points (the jagged islands in the boundary). The best size sits at the bottom of that U-curve, and a bigger minimum leaf size smooths the boundary at any depth.

18.1.4 Handling missing input features

Suppose x is observed except for one feature. A depth-3 tree is fitted below. Two standard remedies when a node tests the missing feature: fractional (follow both branches, weighted by the fraction of training data that went each way) or surrogate splits (use another feature whose split best mimics the primary split on the training set).

missing method
Why it works: if the missing feature were known, the true p(y|x) would lie somewhere along the dashed line. Fractional descent averages the leaf probabilities by marginal frequency (a form of marginalising over the unseen feature). A surrogate works when features are correlated, as they are along the moons, because the other feature then carries much of the same information. It can fail when features are independent.

18.1.5 Pros and cons: axis-aligned splits and high variance

Two classes are separated by a line whose direction you rotate. The dashed line is the true boundary. Press “resample” to draw a new training set of 60 points per class and watch the tree change.

Cons: a tree can only cut parallel to axes, so a diagonal boundary needs a staircase of many splits (rotate to 45° with depth 2). The tree is also unstable: a small change in data can change the top split, which changes everything below it, so the boundary jumps around between resamples (high variance). Pros: it is fast, interpretable, handles mixed feature types and needs no scaling. The variance problem is precisely what ensembles (next tab) attack.

18.2.1 Stacking

Ensemble learning combines several base models fm into f(x)=Σm wm fm(x). Stacking learns the weights. Base models: polynomial fits of degree 2 (underfits), 5 and 12 (overfits). Grey = base models, purple = ensemble, dashed = truth.

Why held-out data: the degree-12 model has the lowest training error, so weights fitted on the training set shift to it and the stack inherits its overfitting (tick the box). Weights fitted on data the base models never saw reward models for generalising. The text uses cross-validated predictions for this, so that no data is wasted. Constraining w≥0 is a mild regulariser that helps a lot in practice.

18.2.2 Ensembling is not Bayes model averaging

BMA weights models by posterior p(m|D)∝p(D|m)p(m) and predicts Σ p(m|D) p(y|m). Three models say x~N(μm,1) with μm∈{−1,0,1} and uniform prior. Data come from N(μ*,1).

Why they differ: BMA assumes exactly one model is the true data-generating process and expresses uncertainty about which. As N grows, the evidence concentrates on a single model (top plot), so BMA ends up as that one model, even when the truth lies between models. An ensemble such as stacking enlarges the hypothesis space to weighted combinations, and its weights do not have to collapse as N grows. Where the truth is not in the model set (the “M-open” case), the two can behave quite differently.
